Cloud computing means using computing resources over a network instead of
owning and maintaining all the hardware yourself. A provider operates
data centers and offers resources such as servers, storage, and databases.
You choose what you need and pay according to the provider's terms.

For example, you could run a website on a rented virtual server instead of
buying a physical server for your home. You still need to configure and
secure what you use.

## Service models

The service model describes how much the provider manages for you:

- **Infrastructure as a service (IaaS):** You rent basic resources such as
  virtual machines and networks. You manage the operating system and the
  application on a virtual machine.
- **Platform as a service (PaaS):** The provider manages more of the
  platform. For example, you deploy application code to a managed
  application service without managing its operating system directly.
- **Software as a service (SaaS):** You use a complete application over
  the internet, such as a hosted email service.

Responsibilities vary by service. In every model, check what you must
secure and maintain. For example, you may still need to manage user access
and data even when the provider runs the application.

## Cloud providers

Amazon Web Services (AWS), Microsoft Azure, and Google Cloud Platform (GCP)
are major providers. Their service names and interfaces differ, but each
offers ways to run applications, store data, connect networks, and control
access. Learning those concepts helps you move between platforms later.

## Choose one provider

Pick one provider for your work in this curriculum. Look at local job
listings for roles such as helpdesk, system administrator, cloud engineer,
and DevOps. Note which providers appear often. Your interests and available
learning resources also matter.

Use your choice consistently as you learn. You can learn another provider
later; the underlying concepts will still be useful.

## Before you create an account

The next practice steps ask you to select a provider and create an account.
Read its current signup and pricing terms first. An account may require
billing information, and resources can incur charges even when a free offer
is available. Set a budget or billing alert where available, review what
you create, and remove resources you no longer need. An alert does not
necessarily stop charges.

## Check your understanding

Which model fits each example: a rented virtual machine, a managed platform
for deploying code, and a hosted email app? They correspond to IaaS, PaaS,
and SaaS, respectively. What responsibilities would you still check with
the provider?
